# Phase 03 Plan 34: Weekly email digests and subscription lifecycle

## Objective

Deliver an automatic Hungarian weekly digest of newly published studies (including separate series chapters) and videos, using the user's existing Resend account, Neon subscription records, and Vercel Cron.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md

## Tasks

1. Add confirmation-based signup, a permanent signup page, and signed unsubscribe synchronization. Never reactivate an opt-out through background synchronization.
2. Add Sunday-evening digests, durable publication snapshots and send tracking, empty-week suppression, protected cron authentication, and an authenticated preview/history.
3. Configure the real Resend segment, verified sender, webhook and production secrets when account access permits; verify locally and in production, then commit/push.

## Verification

- Focused tests for windows, token validation, HTML escaping, deduplication and unsubscribe handling; all existing tests, lint and production build.
- Migration and database lifecycle/concurrency probes; public/admin browser checks; reserved provider test-address confirmation, real provider draft validation without a live newsletter blast.
- GTD verification report and production exact-commit deployment evidence. Read reports because GTD can return zero after failed checks.

## Success Criteria

- Confirmed subscribers receive one digest per nonempty week, can unsubscribe, and see Hungarian confirmation/status messages.
- Only published readable studies and published videos appear; series ordering remains visible.
- Provider failures and concurrent/repeated cron calls cannot cause blind duplicate sends. Setup requirements and delivery history are visible in admin.
- User chose separate chapter PDFs and automatic weekly delivery. Full access key,
  chosen sender, verified domain, dedicated segment, webhook and production secrets
  are configured; real reserved-recipient confirmation and broadcast test passed.
