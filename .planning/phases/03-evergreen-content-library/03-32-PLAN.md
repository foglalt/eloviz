# Phase 03 Plan 32: First-visit email signup

## Objective

Give first-time visitors a concise development notice and a reliable way to
consent to future update emails, while giving authenticated editors visibility
into the collected addresses.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md
- @.planning/phases/<phase-dir>/03-CONTEXT.md

## Tasks

1. Add a migration and server-side subscription validation/storage path with
   normalized, unique email addresses and no unnecessary visitor data.
2. Add an accessible first-visit dialog with Hungarian copy, consent,
   dismissal persistence, pending/error/success states, and responsive styling.
3. Add an authenticated subscriber overview and verify validation, build,
   database migration, and representative desktop/mobile behavior.

## Verification

- `npm run test:newsletter`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `npm run db:migrate`
- Browser checks at desktop and 390 px for first display, error feedback,
  dismissal persistence, overflow, and protected admin routing.

## Success Criteria

- A new visitor sees the notice once and can dismiss it without subscribing.
- Valid, consented email addresses are stored once; invalid submissions are
  rejected with a clear inline message.
- Successful signup is acknowledged without navigating away.
- Authenticated editors can review collected addresses and signup dates.
- No newsletter is sent by this implementation.
