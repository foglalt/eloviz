# Phase 03 Plan 35: Newsletter migration readiness

## Objective

Prepare a safe, reviewable exit from Resend without changing the current sender,
provider, schedule or subscribers. User explicitly selected newsletter migration
readiness after asking about crossing free-plan limits.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md
- @.planning/phases/<phase-dir>/03-CONTEXT.md

## Tasks

1. Add an authenticated, uncached portable export combining every local consent
   record with fully paginated Resend contacts/segment membership/suppressions.
   Opt-outs and blocks win; pending/missing/inconsistent records are never eligible.
2. Include local delivery snapshots and a migration checklist covering pause,
   final reconciliation, pending confirmations, old unsubscribe links, DNS,
   delivery reputation, provider-specific implementation and rollback.
3. Verify conflict rules, pagination/failure handling and auth; read-only real
   provider export, browser UI, lint/build, memory evidence, commit/push and live checks.

## Verification

- Pure conflict/pagination tests and all repository suites; real account read-only
  probe verifies all-page access, no mutations and no secrets in export.
- Unauthorized download denied, authenticated download attachment/no-store;
  setup/export UI responsive and live production verified.

## Success Criteria

- Subscribers can be transferred using consent evidence and conservative exclusions.
- Export is complete or fails; it never returns a silently partial mailing list.
- No email is sent and no provider change occurs. Complete provider replacement
  still requires implementation/testing once the destination is selected.
