# Phase 03 Plan 20: First-party content analytics dashboard

## Objective

Add privacy-conscious first-party traffic measurement and a useful admin
dashboard view of overall visitors, page views, and popular public content.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md
- @.planning/phases/03-evergreen-content-library/03-CONTEXT.md

## Tasks

1. Add an idempotent page-view migration with minute-level duplicate control.
2. Track valid public routes through a small client boundary and same-origin API.
3. Add 30-day and all-time counters plus topic/study/video rankings to admin.
4. Verify privacy exclusions, form-independent navigation tracking, queries,
   responsive presentation, migration, and production deployment.

## Verification

- Focused analytics path/bot tests pass.
- The migration applies idempotently and the analytics query works when empty.
- Synthetic page views produce correct unique visitor and ranking counts, then
  are removed.
- Admin users, automated browsers, invalid paths, cross-origin requests, query
  strings, referrers, IP addresses, and search terms are not stored.
- ESLint, strict TypeScript, production build, browser QA, GTD verification,
  repository health, and live deployment checks pass.

## Success Criteria

- The dashboard shows estimated visitors and page views without another service.
- Top-five topics, studies, and videos are ranked for the last 30 days.
- No personally identifying request metadata is persisted.
- Tracking failures never interfere with the public browsing experience.
