# Phase 03 Plan 15: Make admin relationship saves atomic and faster

## Objective

Reduce ordinary study and video admin-save latency and eliminate partial
relationship updates by sending each record mutation and its relationship
replacement queries to Neon as one non-interactive transaction.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md
- @.planning/phases/03-evergreen-content-library/03-CONTEXT.md
- @src/app/admin/actions.ts
- @src/lib/study-publication.ts

## Tasks

1. Preserve the existing study readiness rule, YouTube metadata refresh,
   pending/success UX, revalidation, and redirect messages.
2. Allocate UUIDs before new study/video inserts so the main mutation,
   relationship deletes, and ordered relationship inserts can share one Neon
   HTTP transaction.
3. Verify the action types and production build, then record focused transaction
   evidence and repository health.

## Verification

- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `.\scripts\gtd.ps1 verify -Phase 03`
- `.\scripts\gtd.ps1 health`

## Success Criteria

- A study save uses one transaction for the study mutation plus topic/video
  relationship replacement (after the existing readiness read on edits).
- A video save uses one transaction for the video mutation plus topic/study
  relationship replacement (after the intentional YouTube metadata refresh).
- A failed relationship insert rolls back the corresponding main record
  mutation and all relationship changes.
- The existing Hungarian success/error behavior and public revalidation remain
  unchanged.
