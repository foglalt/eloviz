# Phase 03 Plan 31: Fix Vercel Blob PDF storage

## Objective

Route Vercel Blob authentication correctly for both request-context OIDC and
legacy read-write tokens, prevent silent production PDF storage in Postgres,
and safely migrate the existing database-backed PDF to the connected private
Blob store.

## Context

- @.planning/PROJECT.md
- @.planning/ROADMAP.md
- @.planning/STATE.md
- @.planning/phases/03-evergreen-content-library/03-CONTEXT.md
- @.planning/investigations/2026-08-02-pdf-vercel-blob-fallback.md

## Tasks

1. Replace the environment-only credential gate with explicit legacy-token
   routing and SDK-managed request-context OIDC routing.
2. Reject missing Blob configuration in production while preserving the
   deliberate local/test database fallback.
3. Add regression coverage for credential precedence, OIDC store-ID-only
   configuration, and production fallback prevention.
4. Add a checksum-verifying migration command for database-backed PDF rows.
5. Deploy through the existing Git-connected Vercel project, migrate the
   current PDF only after rollout, and verify Blob, database, and public PDF
   delivery evidence.

## Verification

- `npm run test:storage`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build`
- `./scripts/gtd.ps1 verify -Phase 03`
- Real Blob put/get/delete probe with byte-for-byte verification.
- Post-migration database assertion: Blob storage kind, null `file_data`, same
  byte size/checksum, and working public PDF response.

## Success Criteria

- New production uploads cannot silently place PDF bytes in Postgres.
- OIDC-only and explicit legacy-token deployments both use Blob correctly.
- The existing PDF is present in Blob and no longer occupies `file_data`.
- The controlled public PDF route returns the unchanged document.
